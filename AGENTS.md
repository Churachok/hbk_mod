# Инструкции для AI-помощников

## Контекст проекта

`hbk` — намеренно абсурдный русскоязычный мод для Minecraft. Его тон — сюрреалистичный, чёрный и игровой юмор. Не «нормализуй» названия, лор или уже существующие механики без прямой просьбы владельца: странность — часть дизайна.

## Как работать

1. До изменений прочитай `README.md`, подходящий класс в `src/main/java` и связанные клиентские классы/ресурсы. Код и игровые тесты — источник истины, README обновляй вместе с изменением поведения.
2. Делай маленькие, локальные изменения. Сохраняй namespace `hbk`, существующие identifier'ы, рецепты, сохранения мира и сетевые payload'ы, если задача явно не требует миграции.
3. Логику общего поведения размещай в `src/main/java`, рендер, экраны и ввод — в `src/client/java`; данные, переводы, модели и текстуры — в `src/main/resources`.
4. При добавлении контента проверь регистрацию, клиентский рендер при необходимости, `en_us` и `ru_ru`, модель/текстуру, recipe/loot/worldgen и документацию. Не придумывай несуществующие API Minecraft/Fabric — сначала проверь применяемую версию и соседний код.
5. После Java-изменений запускай `./gradlew build`; для механик NPC и дропов используй `./gradlew runGameTest`, когда это релевантно. Сообщай, что проверено, а что нет.

## Чистота и безопасность

- Не добавляй в Git `build/`, `.gradle/`, `run/`, логи, сейвы, crash-reports, IDE-файлы или личные пути.
- Концепты, исходники генерации и внешние референсы не считаются зависимостями проекта. Скрипты должны быть воспроизводимы внутри репозитория и не обращаться к домашним каталогам.
- Не удаляй игровые ассеты, структуры или данные мира без явного согласования. Не переписывай историю Git и не выполняй массовое удаление вне явно названных каталогов.
- Не меняй версии Minecraft, Fabric Loader/API, Java или Loom как побочный эффект функциональной задачи.
